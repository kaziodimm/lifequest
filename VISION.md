# HABIDOO Vision

## What Habidoo Is

Habidoo is not a habit tracker.

Habidoo is not a task manager.

Habidoo is not a productivity tool.

Habidoo is a **Life Strategy Game**.

The goal is to make real-life progression feel like advancing through a technology tree in a strategy game.

The user should never feel like they are checking tasks.

The user should feel like they are researching, unlocking, and progressing their life.

## Core Philosophy

Most habit trackers focus on tasks.

Habidoo focuses on progression.

The user does not complete tasks.

The user unlocks technologies.

The user does not build streaks.

The user advances through eras.

The user does not chase XP.

The user develops a life.

## Primary Inspiration

- Civilization
- Stellaris
- Duolingo
- Path of Exile passive tree
- RPG progression systems

## Core Loop

1. User opens application.
2. User sees Life Tree.
3. User selects available technology.
4. User starts a mission.
5. Mission requires real-world action.
6. Mission progresses technology.
7. Technology unlocks new technologies.
8. User advances in life.
9. Repeat.

## The Life Tree

The Life Tree is the product.

Everything else exists to support the Life Tree.

The tree must always be the center of the application.

The tree must be visually impressive.

The tree must feel alive.

The tree must feel larger than the user can complete quickly.

The user should always see future goals.

The user should always want to unlock the next node.

## Technologies

Every technology contains:

- name
- description
- requirements
- rewards
- XP
- unlocks

Technologies can belong to categories:

- Health
- Mind
- Career
- Business
- Finance
- Relationships
- Creativity

## Eras

Progression is divided into eras.

Example eras:

1. Foundation
2. Discipline
3. Growth
4. Mastery
5. Leadership
6. Legacy

The user should feel they are entering new chapters of life.

## Missions

Technologies are progressed through missions.

Example:

Technology:

- Cardio I

Requirements:

- 5 training sessions

Mission:

- 30-60 minute workout

The mission must be actively started.

The mission must be actively completed.

## Anti-Cheat Philosophy

The goal is not to eliminate cheating.

The goal is to make honest progression more rewarding than cheating.

Users can always lie.

The application should encourage real action.

Mission completion should require time commitment.

Progress should happen through effort.

## Mission Timer System

A mission can be started.

A mission enters active state.

Timer begins.

Mission can only be completed after minimum duration.

Some mission types require cooldowns.

Example:

Workout:

- 30-60 minutes

After completion:

- next workout available tomorrow

This prevents spam completion.

## Duolingo Principle

The user should always know:

1. What to do.
2. Why to do it.
3. What it unlocks.

Every action should feel connected to visible progression.

## Visual Design

Habidoo should feel:

- premium
- modern
- dark
- strategic
- mobile-first
- visually memorable

Habidoo should not feel:

- childish
- cartoon
- generic productivity
- like a todo list
- like a habit tracker template

Think:

> Civilization + Duolingo + Apple.

## Graphics And Motion

Graphics and animation are part of the product, not optional decoration.

The app should eventually feel game-grade through:

- custom technology icons
- animated Life Tree connections
- unlock pulses
- timer rings
- era transitions
- fog-of-war for future progression
- profile emblems and achievement medals

Motion must communicate progress, state, and reward. It should make the user want to return to the Life Tree.

Every visual effect must support progression, missions, eras, or unlock desire.

## Mobile First

Mobile is primary.

Desktop is secondary.

Every feature should be designed for mobile first.

Every important interaction should be possible with one thumb.

## Future Systems

Future systems can include:

- leaderboards
- guilds
- friends
- teams
- events
- challenges
- seasonal content
- AI coach
- real-world integrations
- health integrations
- financial integrations

These systems must support the Life Tree. They should not replace it.

## Success Metric

The user does not return because of notifications.

The user returns because they want to unlock the next technology.

## Product Constitution

When making product, design, or engineering decisions, check this document first.

If a feature does not support the Life Tree, progression, missions, eras, or meaningful real-life development, it should be questioned before implementation.
